# planner-ffi

Python 和 Java 通过版本 1 的 C 接口在本进程内运行通用规划器。使用两种语言建模的步骤见[建模指南](../planner/BUSINESS.md)。

从仓库根目录执行 `cargo build --release --manifest-path planner-ffi/Cargo.toml`。导出符号、缓冲区所有权和返回码见[头文件](include/planner.h)。顺序为 `planner_create`、`planner_run`、`planner_size`、`planner_read`、`planner_destroy`。输入显式传字节长度，输出为无终止符的 UTF-8 字节。成功后可用同一句柄重新求解，失败后可以读取原始错误并销毁句柄。一个句柄的求解与结果读取应串行执行，多个句柄可以并行。

## 模型协议

每行一条指令，字段用 ASCII 空白分隔，整数用十进制。分配变量、列表组和表达式各自按声明顺序从 0 编号，表达式引用必须指向前面声明的节点。

```text
V <域值...>
L <所有者数> <元素数>
I <工时> <此元素可选的所有者...>
P <组> <前置元素> <后继元素>
E <操作> <参数...>
R <名称的UTF-8十六进制> <H或S> <权重> <非负罚量节点>
O <最小化目标节点>
C <种子> <步数> <毫秒或-1> <线程数> <tabu或sa或la> <ff或bf>
```

每个 `L` 后紧接规定数量的 `I` 行。`O` 和 `C` 各最多一次，省略时分别使用零目标和默认求解配置。不同名字的软约束可与目标同时使用。下表的“节点”均指表达式编号。

| 操作 | 参数与含义 |
|---|---|
| `const`、`var` | 一个整数常量或一个分配变量编号 |
| `add sub mul eq ne lt le gt ge` | 两个节点，比较返回 0 或 1 |
| `if` | 条件节点、真分支节点、假分支节点 |
| `sum max` | 任意数量的输入节点，空聚合为 0 |
| `lookup` | 下标节点，随后为至少一个表值 |
| `load` | 组、所有者，随后为每个元素的需求 |
| `distance` | 组、所有者，随后为逐行展开的整数距离矩阵，仓库在最后 |
| `adjacent` | 组、所有者、前一个元素、后一个元素 |
| `finish` | 组、元素，返回其最早完工时间 |

例如，以下输入要求从 3、5 中选择较小的值。预算允许零步局部搜索，最佳适配构造仍会计算初始解。

```text
V 3 5
E var 0
O 0
C 7 0 -1 1 tabu bf
```

成功响应首行 `S <硬分> <软分> <步数> <状态> <完整标志>`，下一行 `T <Steps|Time|NoMoves>`。随后 `V <取值...>` 给出分配变量（未分配记为下划线），`L <组> <所有者> <有序元素...>` 给出每个列表，`R <名称的UTF-8十六进制> <加权罚分>` 按约束注册顺序列出所有罚分。
