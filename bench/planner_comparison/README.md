# 等时比较 MIC 与 OptaPlanner

本基准比较两个可运行的建模实现。MIC 使用本仓库发布版 Rust 业务规划器。Java 使用 Maven Central 发布的 OptaPlanner 8.44.0.Final、标准规划实体、列表变量及增量评分接口。[本次实测结果](results/2026-11-24/report.md) · [OptaPlanner 官方手册](https://docs.optaplanner.org/8.44.0.Final/optaplanner-docs/html_single/)

下文记录首轮四类算例的实现和比较方法。后续两轮排课优化沿用相同的模型、种子和时限，分别测量首解构造和局部搜索的变化。[排课构造与冲突计分](rounds/paired-scoring/README.md) · [局部搜索诊断与等时复测](rounds/local-search/README.md)

## 共同业务规则

| 算例 | 可行条件 | 要最小化的代价 |
|---|---|---|
| 排班 | 每班选一名合格员工，同一时段每名员工至多一班，每人最多九班 | 全部班次分配给相应员工的偏好成本之和 |
| 排课 | 每课安排时段和教室，同一时段的教师、班级、教室各自不能冲突 | 每节课与偏好时段编号之间的绝对差之和 |
| 配送 | 每个客户恰好访问一次，每辆车载重不超过 48 | 车辆从同一仓库出发并返回的总曼哈顿距离，横纵坐标差的绝对值相加 |
| 生产排程 | 工序上规定的机器，遵守作业内的工艺顺序及机器队列顺序，且没有循环等待 | 最后一道工序的完工时间 |

四份合成算例由固定种子生成。排班有 911 个合法的班次与员工组合。排课占用 160 个教室时段中的 140 个。配送总需求为 360，总容量为 384。生产有 12 组作业，每组 8 道工序。生成器另有合法排程用于检查数据；求解器都从未分配状态开始。[冻结输入](instances) · [生成器与独立验分](cases.py)

## 如何计时和比较

- 每次给一个求解线程 10 秒墙钟时间。每类用相同的五个种子 7、19、43、73、101。一次只运行一个求解器，按轮次切换同一算例两边的先后顺序，同时轮换四类算例的顺序。两边都在常驻进程里为每次搜索创建新模型状态。正式试验前，每个引擎在每类算例上另外预热两次，每次 2 秒。
- 计时从求解入口开始，涵盖构造与局部搜索。输入解析、生成 MIC 模型文本、JVM 启动、创建 Java 求解器工厂及结果序列化在计时区外。首次可行指可行解首次被观测到的时刻。MIC 在完整方案正式提交且硬分为零时记录，OptaPlanner 在最佳解事件中验证已初始化且硬分为零时记录。独立的 Python 验分器对首个和最终方案检查完整性、资格、硬约束，并重算代价。
- 截止成绩使用预算内记录的最好解；原始数据另外保留返回前的实际耗时。未找到完整可行方案的试验计入失败，只有可行方案参与目标值比较。采用中位数，同时公开每次观测与配对胜负，便于查看波动。
- 两边均先构造、再用禁忌搜索，禁忌长度 8。MIC 使用最佳适配构造、通用表达式的增量计分和每步 32 次采样；OptaPlanner 使用原生队列构造、按本业务编写的增量评分器，局部搜索每步收集 32 个可接受候选。排课的房间冲突在 MIC 中比较课程对，在 OptaPlanner 中维护各教室时段的占用数。列表移动和成环候选的处理也因引擎而异。本轮比较反映这两套具体实现、数据与配置。每类一个实例，五个种子衡量同一实例上的波动。[MIC 建模代码](mic_model.py) · [OptaPlanner 计分与搜索配置](opta/README.md)

## 复现

在仓库根目录使用 Rust、Python 3、Maven 和 JDK 17 或更高版本运行以下命令。本次实测 JVM 为 OpenJDK 21。Maven 第一次构建需要访问 Maven Central，依赖只属于对照程序。

```sh
python3 bench/planner_comparison/cases.py
python3 -m unittest discover -s bench/planner_comparison -p 'test_cases.py'
python3 bench/planner_comparison/run.py --out /tmp/mic-opta-run
python3 bench/planner_comparison/summarize.py /tmp/mic-opta-run
```

基准保留每次正式运行及预热的首解、终解、首解时间、实际返回耗时、输入与源码指纹，以及 OptaPlanner JAR 和 MIC 可执行文件的 SHA-256。新运行使用独立输出目录。固定种子与墙钟预算一起使用时，操作系统调度和 JVM 运行状态会影响实际执行的搜索步数。
