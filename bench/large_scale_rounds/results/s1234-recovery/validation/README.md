# s1234 独立核验

在仓库根目录用 Python 3.10 或更高版本重放。脚本读取上一级的正式运行记录，并调用本地发布版求解器重跑等价模型与穷举模型。

```sh
cargo build --locked --release --manifest-path milp/Cargo.toml --example round_probe
python3 bench/large_scale_rounds/results/s1234-recovery/validation/check.py \
  --binary milp/target/release/examples/round_probe \
  --output /tmp/s1234-validation.json
```

脚本用冻结清单的 SHA-256 核对 MPS、MIC 文本模型和 Gurobi 使用的模型导出。它直接读取原 MPS 中各行的系数、方向、右端、变量类型与目标，再对三个版本逐项对照。对上一轮与本轮 MIC 和 Gurobi 归档的每个可行解回调与终解，它逐行检查原始浮点向量，允许最大违反量为 `1e-6`。同时，它将距 0 或 1 不超过 `1e-6` 的列取整，以整数运算再次检查 8,418 条约束、2,945 个二元变量及费用。所有最小化下界还须小于或等于复算出的最佳可行费用。

原 MPS 有一条覆盖行，要求 128 列之中至少一列取一。对每个这样的列，单独假设它取一，取出所有包含它的短行，枚举这些行涉及的全部变量及费用。枚举保留了其他覆盖列同时取一的可能。其余变量费用非负，所以这些局部费用的最小值是该条件下的下界。128 个条件至少一个成立，取各下界中的最小值可独立得到原问题下界 2。所有枚举仅用整数。

脚本还读取原归档核实的 MIPLIB 2017 v37 官方最优值 29，检查每次运行的下界至多为 29、可行解费用至少为 29。该参考值只用于求解后的对账。[MIPLIB 实例页](https://miplib.zib.de/instance_details_s1234.html)

规模变体用种子 817 打乱全部行、列，并更改变量名与约束名。单线程、最多 5 秒和 256 个节点下，检查器把每个回调和终解的列序还原到原始 MPS，再逐行验解。输出保留重排模型的 SHA-256。

五个小模型共穷举 49,152 个二元赋值。四个模型各有 13 列，第五个有 14 列，都用 11 列的覆盖行和若干短行构造。每例各跑 1 个和 20,000 个节点两档预算。足额时必须返回穷举真值或证明不可行。单节点若返回下界，必须小于或等于穷举真值。模型覆盖了以下情况。

- 只激活一列会付出费用 26，同时激活两列可得到全局最优 2。
- 所有单列激活方案都不可行，多列激活可达到最优 2。
- 所有覆盖列都被短行固定为零，原模型不可行。
- 长行乘以负一并反转不等号，最优值为 3。
- 两条不同短行要求任一激活的列支付同一份费用 9。穷举最优为 10，检验生成下界时能正确处理重复出现的费用。

逐次目标、界、终解中取一的列数及每个回调的费用见 [results.json](results.json)。
