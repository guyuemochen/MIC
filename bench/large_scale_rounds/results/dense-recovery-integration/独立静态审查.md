# 稠密第二阶段冷恢复独立静态审查

审查对象为 `/tmp/mic-dense-numerical-recovery` 的稠密单纯形恢复实现及新增测试；只读审查，没有修改生产文件、编译或运行求解。详细设计见 `/tmp/mic-dense-cold-recovery-design.md`。

第一轮检查恢复生产逻辑，第二轮检查新增欠账与计数测试，最后核对实施者源提交 `ace4c1e` 及主线实际合并 `11e1440`（叠加 `cfe0fb7` 的 Phase-1 诊断）。未发现剩余静态阻断。最终生产逻辑与首轮所审一致；本文件不预先声称尚未执行的动态或组合门禁通过。

## 资格、入口与终止

`solve`、首次 `resolve` 和已有热状态的 `resolve` 三个两阶段收口均调用恢复包装；外借工作步版本与普通 resolve 共用原入口。恢复包装只读取本次 attempt 的局部 `phase2_failed` 标志，该标志只在第二阶段 `PhaseOutcome::Failed` 分支置位，诊断字符串不参与决策。旧诊断、真正限额、第一阶段失败、清理失败与最终解构造降级均不能借此触发恢复。

第一次失败时尚有 Phase-1 欠账则停止；入口曾有欠账但已按原流程完整清理、之后才出现 Phase-2 失败，可以恢复。包装最多调用两次 attempt；第二次直接进入无恢复的底层，不递归、不再发放恢复机会，没有新持久重试状态。

## 额度与状态

阶段循环与恢复预算闸共用原调用限额函数。恢复前后均检查原工作步余额、原 iter_call 限额和原绝对 deadline；None 不读钟。冷重建没有调用 start_call 或公开 solve/resolve，没有清 iter_call、iterations_total、hint、Bland 状态、刷新计数和读钟计数，也没有复制外借工作额度。已执行的失败步骤保留费用与统计。

新人工列在重建后、后置预算闸之前立即产生 phase1_pending 欠账；期限在重建中到期时仍会携带欠账退出。只有新一轮完整 Phase-1 清理成功才清账。第二次失败保持原来的状态与欠账规则。

恢复复用原实例的 rebuild_initial_basis，保留当前 bounds、全部原行与割行、目标、布局及行映射。没有用原 Problem 构造无割新对象，也不回滚到失败前的可行性、目标或对偶证明。下一次 sibling bounds 的 snap/swap 规则照旧。

## 测试触达核对

新增测试中，一次有限界故障确实先经过严格守卫失败，再完成冷证明；两次故障停在第二次，未形成循环。迭代 998/999/1000 与工作余额 0 至 4 的边界覆盖首轮失败已支付步骤、恢复前余额耗尽及重解中额度耗尽。

期限前后钩子覆盖零次重建与一次重建后零次第二轮主元，新人工欠账随后可由正常 resolve 清理。cut、当前收紧界、clone 与后续 sibling 测试核对当前 LP 及状态作用域。补充测试覆盖入口 pending=true 经完整清理后发生 Phase-2 故障，两个清理和两个第二阶段主元全部计为四步；健康热 resolve 与无恢复底层的基、rhs 和计数一致。Bland、刷新、读钟、hint、期限和累计计数专测没有重领原值。

原公开入口的非有限方向测试改为连续注入两次失败，以维持其“恢复仍不成功必须诚实停止”的断言；原比值与阶段守卫的底层薄包装保持无恢复，仍直接验证严格拒绝本身。未见通过简单放宽错误断言掩盖失败的改动。

## 保证边界及两引擎对齐

该恢复只在剩余额度内重新尝试完整证明，不修改容差或守卫，不清 B&B 的 limit_hit 或未决子树。FFI 公共签名、状态映射、ABI 与 panic 边界均未变。调用局部资格不会被快照复制；迭代总数不回滚，现有快照补账仍能覆盖恢复工作。

Sparse 仍使用既有整基重因子化重试；Dense 新增冷恢复属于恢复机制差异，不改变两者数学 LP 与成功证明的语义。不能据此宣称 Sparse 的数值失败都已获得同样恢复能力。

刷新后的有限越界并未在本次静态审查中被证明必定源自特定误差项。Dense 的增量 rhs 与累积 binv 重算是不同浮点路径，冷恢复也不保证一定救回 lseu，更不保证性能收益或代替原模型残差认证。动态微测、默认与组合全套、release 验收和真实算例对账由实施者串行执行并保存原始日志。

## 最终集成增量

实际主树 `11e1440` 的 `run_two_phase_attempt` 中，诊断 Scope 只在 `phase1_needed && num_art > 0` 分支开始。所有第一阶段早退及清理结束均按原诊断路径 finish；成功时先结束诊断、退出该块并 drop Scope，之后才进入 Phase-2。因此，第二阶段失败回到恢复包装时没有仍活跃的第一阶段 Scope。

恢复没有调用诊断 reset。第一次已经经过 Phase-1 的调用，其 finish 已关闭采样，冷重试不能覆盖它；第一次没有实际 Phase-1 时未创建 Scope，第二次重建后若确有人工列，可以由该次真正 Phase-1 首次认领采样。恢复前后预算闸提前退出时没有虚造 Phase-1 样本，新人工欠账独立保持。两种组合都未改变恢复资格、预算和求解状态，Sparse 诊断位置未被恢复提交改动。

实施者归档的 `validation-status.json` 记录默认 MILP、planner、包含 ignored 的 release acceptance、work/proof/snapshot/risk 组合与关闭默认的 Dense 专项退出码均为零；这是实施者运行的证据，本审查未重复执行。源文件的 diff --check 通过。对整份证据提交的 diff --check 会报告原始日志末尾空行和红测试补丁的上下文空格，这些属于原始留档，不是生产源码空白问题，不应为了形式检查改写原始证据。
