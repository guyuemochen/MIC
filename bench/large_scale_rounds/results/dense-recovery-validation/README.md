# 稠密第二阶段有限冷恢复验证

基线：`9b213ae`。默认启用的变更只涉及稠密引擎本轮第二阶段数值失败后的额外一次冷重建；稀疏引擎只增加契约注释。最终解构造阶段降级不纳入恢复。

`01-old-red.log` 是先写新测试、尚未改恢复逻辑时的真实失败：相同当前界、源行及割的小 LP 被一次 NaN 方向注入中断，旧实现返回 `IterationLimit/NaN`，新断言要求重新证明已知 `x=3`、目标 `-3`。`old-red-tests.patch` 可施加到基线复现该断言。后续日志保存原始完整输出，不覆盖旧红。

实现只用本次尝试的局部标志识别第二阶段 `Failed`，不读旧诊断决定控制流。只有无人工欠账、真实工作/调用迭代/期限均允许时才重建。重建保留当前界和全部原行/割，新人工立即立账，再查期限/额度，完整重跑两阶段；第二次不再进入恢复包装。累计迭代、调用额度、Bland 状态、刷新及读钟计数、借用工作余额、hint 和绝对期限都不重置。第一阶段失败、真正触限、不可行、无界及最终解终检降级均不触发恢复。

故障注入仅在测试构建中编译，使用线程局部状态并由作用域析构恢复。新增测试覆盖一次有限步后越界可恢复、两次失败仍保守结束、原界/割和行来源保持、热启动/快照/兄弟界、先前人工欠账清理后允许新恢复、未清人工欠账禁恢复、重建前后过期及后续欠账恢复、调用迭代和工作额度的最后一步、旧诊断不提供资格，以及健康冷/热路径、不可行和无界不恢复。重建后期限测试用确定性钩子，不用休眠或竞速。

既有三个非有限方向公共入口测试仍要求失败、NaN 目标及零步；其故障注入改为连续两次，分别污染原尝试和唯一恢复尝试。仅一次临时故障现在应由新测试证明恢复成功。底层安全步守卫测试仍调用无恢复单次尝试，未放宽断言或容差。

验证命令、退出码见 `validation-status.json`，完整日志按序号保存。`02`、`03` 是补齐全部专项前的早期绿测，`05` 是最终十项专项组合。默认关闭的主线第一阶段详细诊断另由主 agent 合并后验证；本工作树不含该并行提交。

本目录没有 lseu、p0201 或任何公共模型计时结果，不宣称修复了真实大算例的证明退步。一次冷恢复仍可能重复失败或增加运行成本，必须另做同源实测。
