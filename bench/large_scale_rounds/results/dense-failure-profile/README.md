# 稠密失败独立诊断

本目录只归档诊断证据，诊断源码所在独立分支 `codex/dense-failure-profile` 不应合入生产。基线是 `11e1440`，先移植仅诊断样本过滤提交 `e1ee05a`；随后只在 `proof_profile` 下记录真实失败点，不改变原算术、守卫、预算、返回值或恢复策略。

每次公开调用由全局单调序号关联（快照不回退此序号），首次尝试 `attempt=0`、唯一冷恢复 `attempt=1`。`site` 直接取实际入口、普通步后、刷新后或刷新非有限失败点，不由迭代数推断。刷新前值在真实主元和计步之后、刷新计数清零之前复制。非有限重算失败时，失败计算值尚未写入 rhs，因此另存实际失败行及 acc 的位模式，并明确 `refresh_completed=false`。

快照最多四份，表格与逆矩阵合计最多二百万格；超过事件限额或写入错误仅写 stderr，不改变求解。超过格数限额仅保留元数据，并标 `snapshot_complete=false`。人工列的原始映射没有追踪，明确为 null；仅在全快照存在且当前基无人工列时，`current_B_reconstructable=true`。不能从 binv 推测人工映射。

所有浮点字段使用 IEEE754 binary64 的无符号整数位模式，解码时按八字节重解释，不作数值转换。`raw_x_bits` 从基值和非基端点构造，没有调用解输出的夹界逻辑。`basis_bounds_bits` 每项依次为下界、存储上界、第二阶段有效上界；人工变量的有效上界是零。`tolerance_bits` 依次为 feasibility、optimality、pivot、integrality、zero。

`step_data` 八槽依次为：入基列 q、出基行 r、旧基列、主元 p 的位模式、delta 位模式、t 位模式、hit_upper 的 0/1、保留零。flip 没有出基行和旧基列，两槽写 u64 最大值，p 槽零，hit_upper 表示翻转后端点。入口失败没有 step。`row_op` 的 0/1/2 分别表示 Le/Ge/Eq；可选行/列索引的 -1 表示缺失；`row_terms_bits` 每个二元组为结构列编号和系数位模式。

原模型来自本二进制的 fresh export，并与冻结 lseu 模型哈希核对。求解命令除二进制路径外与 `dense-recovery-probes/lseu.jsonl` 一致；全部原探针非时间结果字段逐项对账，诊断证据不能用作性能晋升证据。
