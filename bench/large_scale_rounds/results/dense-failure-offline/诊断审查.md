# 稠密第二阶段失败定位与离线分流

基线为 `11e1440`。冷恢复后的 lseu 仍未证明，迭代总数多 400 只能说明额外支付了工作，不能据此断言两次重试各执行了恰好 200 步，更不能单独证明故障发生在刷新。以下只设计诊断与证据分析，不修改容差、LimitReached 纪律或生产恢复策略。

## 第一轮真实诊断

独立诊断分支保持相同模型、默认特性、求解参数、线程数和 30 秒窗口，只额外启用诊断。保存源提交、MILP 树、二进制与模型哈希、原始命令和输出；完成后与 `11e1440` 默认探针逐项对齐所有非时间结果。若诊断开销改变时限出口或搜索计数，这次记录仍可说明内部状态，但不能冒称同轨迹定位。

最多保存四个真实 Phase-2 数值失败。每个公开 LP 调用分配独立单调 call_id，冷重试使用同一 call_id、attempt 从 0 变为 1。该编号是关联标签，不是数学证明，也不能用可能因快照回退的 iterations_total 充当唯一编号。事件应包括实际失败位置：入口、定价、比值过滤、小主元、普通步后、完整刷新后、刷新非有限早退。

每个事件保存 phase、iter_call、iterations_total、刷新计数、phase1_pending、实际基行、基列、有效上下界与失败值。末步记录 pivot/flip、进入列、离基行及旧离基列、主元、delta、t、hit_upper。位置由真实分支写入，不能解析中文错误串或按迭代数整除 200 推断。

刷新前 rhs 的复制位置必须是实际 pivot 和 count_step 之后、refresh_values 之前；这时前后使用同一个新基与同一非基端点。另留重置前的刷新计数。普通步后若没有该向量，应标 null，不能把上一次刷新前的状态当当前步前状态。

非有限刷新在计算 acc 后、写回 rhs[i] 前返回。因此这类事件的 rhs 是部分更新状态，必须另列失败计算的 row 与 acc bits，并标 refresh_completed=false。完整刷新后界违反则标 true，其 rhs 才是完整新值。该诊断边界已经向实施者指出并核对修正。

全浮点以原 IEEE754 u64 位模式输出，避免字符串舍入、NaN/Inf 无法成为 JSON 数字以及正负零丢失。raw_x 从当前基值和非基所贴端点构造，不经过 build_solution 的夹界。全部五项容差也应保留原 bits。

## 失败时一次性快照

为避免第二次复现，可在四次失败时一并保存有界完整快照：有序 row_terms、row_rhs、row_op、row_scale、row_slack、slack sign、constraint_row/cut_row、当前 bounds、basis/in_basis/at_upper、rhs、raw_x、binv、当前 tableau 与内部成本。诊断内存和记录数必须有限，省略必须显式标记。写出错误不能改变 LP 状态。完整快照失败或被容量上限省略时，不能标称可重建当前 B。

第一版允许 artificial_mapping=null，但必须列出基中人工列及其数量。只有快照完整且基中没有人工列时，才能标 current_B_reconstructable=true。此时虽可能还有非基人工列，构造当前基矩阵不需要它们；静态列的残差校验也不需要猜人工列来源。

如果故障基中仍有人工列，下一轮诊断必须从初始 rebuild 和 add_row 创建人工列时正向记录 (原始行, sigma)。存量人工列遇新增静态松弛列会整体右移；映射宜以人工段相对次序保存，并覆盖 clone、重建、追加割。不能从演进后的 binv 或 tableau 近似反推人工列。没有映射时本轮仍可定位刷新前后差异，但不能宣称已正确组装完整 B。

## 可执行的离线分析顺序

先校验维度、基列唯一性、in_basis 与 basis 一致性、所有行/列映射范围、非基端点合法性、原始 bit 解码与 full 标志。以下记 B 为按当前 basis 顺序、由保存的原始内部系数组装的基矩阵，R 为保存的累积 binv，M 为当前 tableau，xN 为当前非基端点。

结构列 j 的第 r 项直接取 row_terms[r] 的 j 系数；松弛列 c 由 row_slack[r]=c 和 slack sign 生成带符号单位列。不要从 M 的基列单位阵构造 B，那只是在验证程序已强制写成单位阵的表格表示。

1. 按生产 refresh 的相同有序乘加和跳零规则计算 `d64 = row_rhs - Σ非基结构列 a*xN`，再计算 `x_replay64 = R*d64`。对完整刷新事件逐位核对 x_replay64 与 rhs；不一致先调查采样时点、矩阵/界快照或离线运算顺序，不先推断算法错误。
2. 用精确表示这些 f64 的值（Python `Decimal.from_float`，例如 80 与 160 位复算，或标准库 Fraction 的精确有理数）计算 `d_exact = b - N*xN`。同时计算 `R*d64` 与 `R*d_exact` 的高精度乘加。这样分别测量末次乘加舍入、构造 d 的舍入与累积 R 自身误差，不能把它们混为一个“逆矩阵漂移”。
3. 独立解 `B*x_fresh = d64`，并用高精度解 `B*x_reference = d_exact` 作对照。前者可先用现有 Sparse LU；后者不应把普通 f64 新解直接称为真值。两种高精度结果需稳定，必要时再做精确有理解；高精度稳定本身仍不是普遍的严格认证。
4. 对刷新前、刷新后与新解分别计算原等式残差 `B*x - d_exact`，记录绝对最大值、对应行及按 `|B|*|x|+|d|` 归一的后向误差。并逐项按原绝对 feasibility 检查所有基本值；结构变量使用当前 bounds，松弛下界零，Phase-2 人工若可组装则固定零。
5. 检查 `R*B-I`、`B*R-I`、静态列的 `B*M-A` 与 `M-R*A`。这些量区分累积逆矩阵、表格列和 rhs 各自的不一致。若 M 与 R 已分离，仅替换 rhs 不能让下一轮定价/方向与新基本值一致。
6. 对同一 call_id 的两个 attempt 比较实际基列、非基侧、bounds、当前行集合、R/M 误差及失败值，确认冷重建是否真回到同一坏基，还是不同基发生相似故障。不能因多了 400 次迭代就断言路径相同。

如果普通步后直接失败而无刷新，当前最小快照不包含全部旧 rhs/alpha 的位级副本；届时再有针对性加一次前步向量捕获，逐位复演预检与更新，不在首次探针为所有主元保存大轨迹。

## 现有 Sparse LU 的复用可行性

`simplex_sparse.rs` 已有 `factorize_into(cols, pivot_floor, m, LuFactors, LuScratch)`，输入就是原始行空间的稀疏列 `Vec<(row,value)>`，不要求先建立整个 CSC 引擎。`ftran_dense` 解 Bx=d，`btran` 解转置系统。三者当前私有；将来若证据支持，只需一个窄 `pub(crate)` 包装，无须新增 LU 算法、外部依赖或 unsafe。离线诊断可先在独立 feature 下暴露只读分析包装，不接入求解恢复。

须正确处理 Q 列置换：既有 Sparse refactor 先排单位列、再按非零数排结构列，因子化后把 col_perm 设回原基位置。独立包装若保留这一顺序，ftran 返回必须仍按 basis 位置；若不重排，则显式用单位列序。先以 B*x≈d 验证映射，不能将置换接错造成的异常误报为数值问题。保留保存的原 pivot 阈值，因子化拒绝就记录拒绝，不能离线悄悄降阈值后称生产路径可恢复。

若未来用 fresh LU 恢复 Dense，必须重建彼此一致的 rhs、全静态表格列及 binv，而不是只把 rhs 改成 fresh x；定价、方向、割读取、对偶、之后的 refresh 都依赖这些状态。该工作要先在暂存中完成并验证，再原子替换；其成本和预算纪律另审。本轮不实施这个生产变化。

## 证据分流与后续算法方向

若高精度同 R 乘加消除了失败而 fresh B 与之接近，优先调查刷新乘加与 d 的抵消，评估补偿累加或有严格前后残差检查的迭代改进。若同 R 的高精度结果仍明显错误、R*B-I 大，而 fresh B 解在原界内且残差好，才有证据支持一次从原系数重建当前基表示。

若高精度 fresh B 解也超界，当前基对真实内部行已不可行；不能夹回界、删除 refresh 或继续原始 Phase-2。需要先以一致的新基表示做受原预算约束的可行性修复，或诚实停止。现有 dual repair 是候选，但必须另审其全调用迭代、期限及工作额度，不能把重构成功当作可以无限再跑修复的许可。

一个需要验证的机制是离基贴界误差积累：每次接受的离基残差虽不超过 feasibility，随后非基值取精确端点，而增量 rhs 与真实等式的关系仍可能累计舍入/贴界差；病态基可放大这种差。该机制可以解释“步前基本界检查通过、重算后越界”的可能性，但在 B*x-d 与记录分析之前只能列为假设。

若 fresh 因子化失败、基接近奇异或高精度结果对精度仍不稳定，先定位基选择及累积方向错误，保持 LR；不能把“换了一个解法给出数值”当作最优证明。任何后续方案都不修改现有严格容差、不清 limit_hit、不重领迭代/期限/work，也不因 obj 与显示 bound 相等而宣布 Optimal。

## 本轮实际采样后的已确认事实

实施者已在独立源码 `97cc7eb` 完成唯一一次 lseu 探针，报告 23 项非时间字段与恢复基线完全一致。本审查读取了 `failure-summary.json`：call_id 17086 与 17153 都分别在 attempt 0 的 iter_call=200、attempt 1 的 iter_call=400 失败；四次真实 site 均为 phase2_post_refresh，refresh_counter_before_reset=200、refresh_completed=true、pending=false。

四次唯一违反行均为 row 74，basis column 52，当前界 [0,1]。第一调用刷新前 `0.9999999993187958`、刷新后 `1.000000822976822`；第二调用刷新前 `0.9999999992834974`、刷新后 `1.0000008235908044`；各自重试的这两个值完全相同。故“完整刷新使该基本值从界内变成超界”现在是直接记录，不再只是 +400 迭代带来的猜测。原因属于累积 R、乘加抵消还是当前真实基不可行，仍待上述离线对账。

四份快照均完整、当前基中人工变量数量为零，可直接重建 B；无须为本轮这四份数据新增人工映射。原始快照位于 `/tmp/mic-dense-failure-profile/bench/large_scale_rounds/results/dense-failure-profile/lseu-failures.jsonl`。审查者没有启动求解或离线矩阵重算，动态探针由实施者执行，离线分析由主 agent 接手。
