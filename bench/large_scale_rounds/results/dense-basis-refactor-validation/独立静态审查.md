# 稠密当前基重分解独立静态审查

审查对象：`/tmp/mic-dense-basis-refactor` 中 Dense 当前基重建、Sparse LU 窄封装及新增回归。已完成两轮静态审查，目前没有剩余静态阻断。审查者没有编译、运行求解器或重新解离线矩阵；只读代码、日志摘要，并对原快照做了 JSON 结构、列映射与 raw_x 位模式核对。

## 证据边界

独立核对主 agent 的离线脚本后，确认它用保存的内部原行、松弛符号和当前 basis 正确构造 B，非基结构端点与当前 bounds/at_upper 一致；Fraction 残差针对保存的二进制浮点输入，NumPy 候选仍是普通双精度解。全部四份快照的生产刷新逐位复演一致；保存逆矩阵与 B 的乘积明显偏离单位阵，而新基解满足现有基本界和当前行残差门。这支持重分解当前基的实验方向，不构成精确最优/不可行证书。

原快照有 83/82 个旧人工列但无人工基，所以“无人工基、所有人工非基贴零”才是适用条件，不能简单要求 num_art=0。该区别在实施中得到保留。

## 控制流与预算

恢复资格仍只来自本轮 Phase-2 Failed 的局部标志，旧 diagnostic 不提供资格，旧 Phase-1 欠账不被抹去。先在临时状态准备 fresh；准备成功则提交并直接进行唯一第二次 Phase-2 attempt，准备不可用才走既有 cold 与唯一完整两阶段 attempt。fresh 提交后再次失败直接停止，没有第三次 cold 尝试，没有递归或新持久重试状态。

原 iter_call、iterations_total、hint、外借 work、deadline、Bland 与维护计数均不重置。因子化后、逐列求解前、准备后、提交后均有期限门；准备过程发现期限后返回，外层再次读取原停止条件，不能把它当数值不可用继续 cold。None 时不读钟。准备不计主元步，已执行步骤不退款；真正触限仍返回原停止状态，B&B limit_hit/未决规则完全不改。

## 基列、三角求解与一致性

B 仅由 row_terms、row_slack 与保存的 slack sign 按当前 basis 位置构造。新 LU 封装复用既有 factorize_into，未修改 Sparse 的共享算术或阈值。输入检查有限性、范围、正且有限的 pivot_floor，以及每列行号严格升序唯一；成功后核对因子维度、索引、有限性、对角门槛和 perm/order 完整置换。单位列优先排序后 col_perm 正确映射回原基位置。

新 rhs、R 和 M 均由同一新 LU 产生：rhs 解 d，R 的第 k 列解 e_k，M 的每个静态非基列解原 A_j，基列填单位阵。R 存储方向为 R[i][k]，没有转置错误。每次求解检查原 B 方程的绝对残差；还检查全部新基本界、当前结构行 Le/Ge/Eq 可行性与带松弛等式的一致性。所有门沿用原绝对 feasibility/pivot，未用 10*feas、按当前算例调阈值或夹界替代。

非基静态松弛必须贴零下界，不能把上界标记为真的无穷松弛静默当零写进 d。这个首审补充已实现并有拒绝测试。有限输入的中间溢出通过 LU 因子和 FTRAN 输出检查保守拒绝；没有 catch_unwind 当常规数值策略，也没有新增经验幅度门。

## 原子提交与人工退休

所有可能返回数值不可用的构造、求解和校验在临时矩阵中完成。提交一次性替换 M/R/rhs，静态 basis、当前界、原行/割行、layout 及目标不变。仅在 pending=false、人工均非基零侧时退休旧人工列，设置 num_art=0 并截短相应标记数组；这不会删行或放松 Phase-2 LP。残基人工或非法侧标记会使 fresh 不适用，仍走原 cold。

提交随后重判 nz_enabled 并重建全部行索引或清空禁用态索引，覆盖人工列退休导致的阈值跨越。若提交后期限到期，保存的是可继续使用的静态新基，仍诚实停止；cold 产生的新人工欠账沿用已审纪律。快照复制的是正常引擎状态，不会复制本次局部恢复资格或重领工作额度。

## 回归触达与未作的断言

已静态核对最小保存逆漂移、两份真实112行快照重建、Ge负松弛/上下端点/非零下界/割、人工退休跨索引阈值、临时准备失败不污染、准备后期限不提交、提交后期限保持有效新状态、残基人工及非法非基侧拒绝、列置换和非有限/小主元/溢出拒绝。旧恢复测试改为明确区分 fresh_prepares、fresh_commits 与 cold_rebuilds，减少的迭代来自不重放旧冷路径，不是免除已付步骤。

静态结论没有覆盖所有可能的浮点病态输入，也没有把恢复残差门称为精确认证。新封装对 Sparse 只是工具复用，Sparse 的恢复策略未被改写。动态完整门禁、真实 lseu 证明与最终原模型对账、性能及内存影响由实施者和主 agent 在受控 CPU 窗口完成；本文件不冒称审查者亲自执行这些测试。
