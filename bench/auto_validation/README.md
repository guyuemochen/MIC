# 自动搜索配置：独立验证集与预注册规则

本文件和 manifest 在首次性能评测前冻结。生成过程只创建模型，不调用求解器。
当前证据支持“部分较难的多维背包适合混合搜索”，不支持“所有 packing 都适合”。

## 已有证据与候选结构

主分支 5b98c70 的历史对照中，mknap-5x300 的同口径 DFS/混合为 5.2056/1.3572 秒，
但 mknap-3x100 为 0.0617/0.0851 秒，stein27 为 3.3773/4.4297 秒。
混合在大背包上的峰值 RSS 从约3.7MB增加到37.5MB。历史对照关闭局部割和RC固定，
因此不能把它直接当作自动配置相对默认配置的收益。最终CLI单开混合约12.5%改善，
混合加关闭RC固定约1.41秒，说明配置之间存在明显交互。

设计审查建议：输入域先限定单线程、纯二元、最大化、正目标、非负系数的全部 Le 约束，
排除覆盖、等式、负系数、连续变量。此规则只识别 packing，不能预测树难度。
若使用根 LP 分数变量数/比例、根松弛间隙等信号，应确保该信号来自相同原配置与相同求解时点；
不得为了选择配置重做整段根求解却漏算选择成本。不得用文件名、精确尺寸、已知最优值或墙钟作判别。
主agent已冻结本轮候选：200≤变量数≤512、2≤行数≤16，加上上述packing条件，
命中采用hybrid+localoff+RCoff，显式覆盖优先，其余保持原配置；不引入额外LimitReached。
边界检查必须在实际选择点重新计算结构（预处理可能改变维数或消去负系数行），不能仅凭生成参数断言命中。
结构阈值必须先冻结，再评估本集合；看过本集合成绩后调阈值，就必须另换种子作为最终验证集。

## 独立生成集

```bash
python3 bench/auto_validation/generate.py --output /tmp/mic-auto-validation-v3-cases
```

21个模型，manifest列出全部种子、参数和SHA256。重复运行逐字节核验；不同内容拒绝覆盖。
脚本拒绝写入任何 bench/instances 子树，不写 `.opt`。本次仅在上述临时目录生成，未提交模型大文件。
未对生成模型声称已知最优值，manifest 的 known_optimum 全为 null。

- 两个独立种子各生成：80变量/2行、160/4、240/7、300/5四档packing，共8例。
- 容量比例从1/2、1/5、1/8至1/6；最后一档价值与平均重量相关，避免只复制原生成分布。
- 199/200/512/513变量边界、1/2/16/17行边界，共6例，检查本轮冻结门控。
- 另有300变量/8行的稀疏packing（25%密度）；220变量/4行的Min、负目标、负系数、Ge四个负控。
- 覆盖60行100变量与120行200变量各1例，作为不应误选packing策略的负控。

“小/中/多行/相关”描述结构，不能预先声称容易或困难；实际难度须由限时实验确认。
本集合规模有限，不覆盖百万变量或混合整数的一般分布；稀疏和符号负控仅各一个种子，覆盖仍薄。

## 预注册实验与验收

每例固定同一构建、threads=1、相同预处理/根割/启发式/容差/时限；建议30秒硬求解预算，
外部看门狗另加5秒并明确记录强杀。禁止混用主动降级与完整时限结果；实际参数逐条写入原始JSONL。
至少比较：原默认DFS、DFS+localoff+rcfixoff、显式hybrid+localoff+rcfixoff、auto四组。
自动配置测量包括结构判别和选择成本。按例交替顺序配对至少3次，报告中位数和范围；
CPU空闲时串行执行，计时期间不编译、不跑其它测试。

在读取验证集成绩前固定以下保留条件：

1. 正确性：不得出现错误终态、未经审查的目标冲突或非法解。所有解独立重算目标并检查变量界、整数性、原约束。
   两个Optimal必须目标一致（绝对误差≤1e-7×max(1,|目标|)）；不同终态逐例审查。
   限额结果只能LimitReached；双方到限时比较可行解、有效对偶界与gap，不按耗时假装谁更快。
   自动配置不得让原默认已证明最优的实例在相同预算下失去证明；新增模型至少用HiGHS/SCIP一种独立实现核对。
2. 性能：只在双方都证优且基线中位≥0.1秒的实例计算时间比；命中域几何平均时间比≤0.90，
   全集合该指标≤1.00，单例不能>1.25。未命中域不允许改变求解配置，计时回退上限10%；
   亚0.1秒实例主要对比确定性工作量，耗时只记录不作为百分比通过/失败依据。
3. 内存：逐进程测峰值RSS，记录平台单位（macOS为字节）；不得用累积子进程最大值替代当前实例值。
   每例auto峰值≤max(64MiB, 2×原默认峰值)，且绝对峰值≤256MiB；超出则本轮不设为默认。
   规则允许小基线的固定开销，但不能隐藏大量完整父域快照的扩张。
4. 确定性：无墙钟截断的threads=1双跑目标位模式、状态、节点/LP迭代、割数、解向量全部相同。
   另用固定节点预算验证触发上限时返回LimitReached且前沿界完整；墙钟限额下不要求节点逐次相同。
5. 覆盖：必须报告每例选择的策略、全部阈值、命中数与未命中数。若独立packing少于3例命中，
   视为适用域证据不足，不因“零回归”就推广默认。不得剔除负收益、超时、无解或内存超限记录。

上述阈值是本轮工程验收选择，不是统计显著性结论。三次计时和少量生成模型仍不足以代表实际业务分布。
若失败，保留显式配置及实验记录；不要按验证结果反复调门槛直到通过，再称其为独立验证。

主agent执行预算补充（首次性能前冻结）：21例先各模式1次5秒筛查，再对上述4个域内packing种子、
稀疏packing与关键负控各3次10秒配对，记录峰值RSS、状态、目标和界。5秒筛查只查错误和明显退化，
不能据其修改判别阈值。10秒未证明的实例按限额结果评估；若有效证优样本不足，结论为证据不足，
不把短预算方案替代上文30秒建议后仍声称已通过完整性能验收。
